## Requirements

### Configuration and engine

1. `app/config.py`: `database_url` becomes `str | None` with default `None` (today it defaults to a local URL, which would make "is a database configured" impossible to answer). Add `database_url_unpooled: str | None = None` (env `DATABASE_URL_UNPOOLED`, used only by migrations) and `database_schema: str | None = None` (env `DATABASE_SCHEMA`). The URL fields must never appear in a `repr`, a log line or an error message (hidden fields, with a test, as `session_secret` already is). A helper accepts `postgres://`, `postgresql://` and `postgresql+psycopg://` and returns the `postgresql+psycopg://` form; query parameters such as `sslmode` and `channel_binding` are passed through untouched.
2. `app/infra/db.py`: one `MetaData`, and `create_db_engine(settings)` returning a SQLAlchemy 2 engine with `NullPool` (each serverless instance connects through the provider's pooler), `connect_args={"prepare_threshold": None}` (the pooler runs in transaction mode and does not support prepared statements) and, when `database_schema` is set, `execution_options(schema_translate_map={None: schema})`. Do not use the connection `options` startup parameter or `SET search_path` at runtime: the pooler rejects them. Creating the engine must not open a connection.
3. Timestamps are `timestamptz`. The driver returns them in the session time zone, so every adapter converts what it reads with `.astimezone(UTC)`, and every value it writes is already timezone-aware.

### Schema and migrations

4. Alembic in `backend/migrations/` with `alembic.ini` (no URL in it). `env.py` reads `database_url_unpooled`, falling back to `database_url`; when `database_schema` is set it runs `SET search_path TO "<schema>"` on its own connection (a direct connection, so this is allowed) and keeps the version table in that schema. One hand-written revision `0001` (no autogenerate), with a working `downgrade`:
   - `users`: `id integer generated by default as identity` primary key, `name text`, `email text`, `role text` with a check for the four values of `Role`, `password_hash text`, `created_at timestamptz`, `version integer not null default 1`, all not null, and a unique index on `lower(email)`.
   - `sessions`: `token_hash text` primary key, `user_id integer` references `users(id)` on delete cascade, `created_at timestamptz`, `last_seen_at timestamptz` (all not null), and an index on `last_seen_at`.
   - `customers`: `id integer generated by default as identity` primary key, `name text not null`, `email text not null`, `phone`, `tax_id` and `address` as nullable `text`, `status text not null` with a check for `active` and `inactive`, `version integer not null`, `created_at` and `updated_at` as `timestamptz not null`, `name_search text not null` and `email_search text not null` (the `normalize_for_search` form of each, written at write time and never computed by the database), a unique index on `lower(email)`, and an index on `(created_at desc, id desc)`.
5. `app/cli.py` (run as `uv run python -m app.cli <command>`): `migrate` runs `alembic upgrade head`; `seed` loads the four seed users (`seed_users(demo_password_hash())`) and the ten seed customers only into empty tables and then moves the identity sequences past the highest id, so running it twice changes nothing. Neither command prints a URL or a secret.

### Adapters

6. `app/modules/auth/adapters/postgres.py`: `PostgresUserRepository(engine)` and `PostgresSessionStore(engine, max_sessions=MAX_SESSIONS)`. SQLAlchemy Core (`Table`, `select`, `insert`, `update`, `delete`), one `tables.py` per module for the `Table` objects. The session store follows the port exactly:
   - `create` counts and evicts in one transaction, serialized by `pg_advisory_xact_lock` with a constant key, evicting the oldest `last_seen_at` first and never evicting the session being created; creating a token that already exists replaces it, like the in-memory store.
   - `touch` is monotonic in SQL (`last_seen_at = greatest(last_seen_at, :when)`) and a no-op for an unknown token.
   - `purge_older_than` returns the number of deleted rows (strictly older than the cutoff).
   - Add `replace_all(users)` to the user repository (not part of the port) for the seed and the nightly reset: it replaces the users, deletes the sessions, and resets the identity sequence.
7. `app/modules/customers/adapters/postgres.py`: `PostgresCustomerRepository(engine)` implementing every sentence of the docstrings in `ports.py`:
   - `add`: one `INSERT`; the unique index on `lower(email)` is the only check, and its violation (SQLSTATE 23505 on that index) becomes `EmailTaken`. No check-then-insert. Fill `name_search` and `email_search` with `normalize_for_search`.
   - `update` and `set_status`: one transaction that starts with `SELECT ... FOR UPDATE` on the row, then the checks in the documented order (not found, version, email taken, no change), then the `UPDATE`. A request that changes nothing returns the stored customer untouched. Keep the search columns in step with `name` and `email`.
   - `list`: `q` is literal text, so use `contains(..., autoescape=True)` (or an explicit `ESCAPE`) on `name_search` and `email_search` with `normalize_for_search(q)`; filter by status; order by `created_at desc, id desc`; the total is a separate `count` with the same filters; `OFFSET` and `LIMIT` from `page` and `page_size`.
   - `replace_all`: replace the rows inside one transaction (`DELETE` then `INSERT`, explicit ids) and move the identity sequence to the highest id plus one (1 when empty); this must work with `pg_get_serial_sequence` on an identity column.
8. Wiring in `app/modules/auth/container.py` and `app/main.py`: when `settings.database_url` is `None` nothing changes; when it is set, build the engine once (stored in `app.state.engine`) and use the PostgreSQL adapters for users, sessions and customers. Creating the app and `GET /api/health` must not open a connection (the health check stays database-free). Seeding is not done at startup.

### Keeping the unit suite away from the database

9. A developer's `backend/.env` will contain `DATABASE_URL`, and `Settings` reads it. The unit suite must never touch a database because of that. Add an autouse, session-scoped fixture in `tests/conftest.py` that removes `DATABASE_URL`, `DATABASE_URL_UNPOOLED` and `DATABASE_SCHEMA` from the environment and makes `Settings` ignore the env files (for example by setting `Settings.model_config["env_file"]` to `None` for the run). Prove it with a test: with a `.env` file containing a database URL in a temporary working directory, `Settings()` built inside the suite has `database_url is None`.
