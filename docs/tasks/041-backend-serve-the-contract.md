# Task 041: serve the API contract and its documentation

Assignee: Worker 1. Branch: `w1/serve-contract`. Reviewer: Supervisor.

**Base.** Branch from the tip of your latest branch (the one that has the committed contract of tasks 030 and 036), or from `main` once the supervisor has merged them.

## Goal

The contract is a committed file, but a person testing the online demo cannot fetch it from the running application, and FastAPI's interactive documentation is mounted at paths that the deployment does not route (the platform sends only `/api/*` and `/__test__/*` to the API). Serve the contract and the interactive documentation under `/api`, without changing the contract itself.

## Read first

`backend/app/main.py` (`create_app`, the middleware order), `backend/app/guards/` (the controls guard, the origin check, the rate limiter, the request controls: which paths each one looks at), `backend/app/openapi.py` if it exists (task 036), `backend/tests/test_openapi_contract.py`, `vercel.json`, `docs/DEPLOYMENT.md`.

## Scope

You may edit `backend/app/main.py`, the guards only if a path predicate needs it, `backend/tests/`, `backend/README.md`, `docs/DEPLOYMENT.md` (one line: the documentation is reachable online at the two paths) and `docs/openapi.json` only if it changes (it must not). No new dependencies. Do not change any other route or answer.

## Requirements

1. `GET /api/openapi.json` returns the OpenAPI document (the same as `app.openapi()`; `Content-Type: application/json`); `GET /api/docs` returns the Swagger UI page. Set `openapi_url="/api/openapi.json"`, `docs_url="/api/docs"` and `redoc_url=None` in `create_app`; the old paths (`/openapi.json`, `/docs`, `/redoc`) answer the standard 404 problem.
2. Both are public (no session needed) and subject to the rate limit of `/api/*` like any other path, and exempt from the origin check (they are `GET`). Verify, by reading the guards and by tests, that the request controls middleware does not open a database connection for them when the controls are disabled, and does the normal work when enabled (they are under `/api/`).
3. The document served is exactly `docs/openapi.json` (a test compares the served JSON with the committed file; the committed file keeps being generated by the CLI as in task 030).
4. The Swagger page must work with the session cookie of the application: "Try it out" calls `/api/...` on the same origin, so the browser sends the cookie; say in the README that a user logs in on the web app first. No custom CSS or scripts.
5. Tests: the two paths for an anonymous user and for a logged-in user, the content types, the old paths answering 404, the served document equal to the committed file, the rate limit counting these requests, the controls on and off, and that `/__test__` is still guarded.
6. Docs: a short "OpenAPI contract online" paragraph in `backend/README.md` and the one line in `docs/DEPLOYMENT.md`.

## Acceptance criteria

From `backend/`, all of these pass:

```bash
uv sync
uv run ruff check .
uv run ruff format --check .
uv run pytest -q -W error
uv run python -m app.cli openapi --output ../docs/openapi.json && git diff --exit-code ../docs/openapi.json
```

and, manually, with the server started as in the backend README: `curl -s http://127.0.0.1:8000/api/openapi.json | head -c 200` shows the document and `curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/docs` is 404.
